# RyzeMP 1.0.0-beta.5 · Bedrock inventory and login fixes

This prerelease includes **both** confirmed corrections from the Bedrock 1.26.60 server logs:

1. **ItemStackRequestPacket decoding:** updated the *published Composer dependency* `ryzemcbe/bedrock-protocol` to `v1.0.0-beta.3` (BedrockProtocol PR #17). The version-specific wire mapping accepts the 2225 `CraftResults` action encoded as `outer type 18 / inner type 20`, and preserves correct 2168/2169/2193 action mappings. Malformed requests continue to be rejected.
2. **Command metadata login crash:** skip empty command overloads when inspecting parameters in `CommandMetadata::describeCrateOverloads()`. A secondary exception guard prevents optional command tracing from interrupting `NetworkSession::syncAvailableCommands()` and the NetherNet pre-spawn flow.

The release workflow installs dependencies directly using the committed `composer.lock`, checks for the official beta.3 package and inspects the finished `RyzeMP.phar` to confirm both fixes are bundled. This prevents accidentally releasing the earlier beta.2 inventory codec.

No changes to player IP/port, native RyzeRTC API 2, PHP 8.4 ZTS Linux x86_64 requirements, plugin API, worlds or server configuration. The RyzeRTC native `.so` and its libraries remain **outside** the PHAR and are managed by the egg.

**Validation:** PHP regression tests, versioned Bedrock protocol integration, PHAR archive inspection, native shared-port signaling/RakNet smoke test, synthetic client pre-spawn and world spawn, and public plugin-command smoke tests. These automated checks are not a substitute for real Minecraft 1.26.40/1.26.52/1.26.60 client joins and inventory interactions. Release only after all CI jobs are green.

**Pterodactyl update:** choose `RYZEMP_CHANNEL=pruebas` and use **Reinstall** once this official prerelease is published with `ryzemp-update.json`. The updater checks SHA-256 and preserves worlds/plugins/configuration, NetherNet operator identity, and the previous software version for recovery. A plain restart does not download a new PHAR.

The optional one-time diagnostic introduced earlier is retained and isolated from login. Investigations of unrelated command autocomplete behavior are out of scope for this bugfix release.
