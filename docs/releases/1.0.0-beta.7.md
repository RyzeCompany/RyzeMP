# RyzeMP 1.0.0-beta.7 — Vanilla world creation from the Egg

This prerelease follows the already-published immutable beta.6. It does not alter beta.6 artifacts.

## Fixes

- Support `RYZEMP_VANILLA_WORLDGEN=true` at server startup using RyzeMP's built-in Vanilla generator and `VanillaDataManager` data preparation.
- Existing servers: create an additional world, `worlds/world_vanilla_auto`, without changing the configured default world or modifying `server.properties`, `pocketmine.yml`, existing worlds, plugins or NetherNet identity.
- New servers already configured for a Vanilla default world: do not create a redundant extra world.
- If the Vanilla data cannot be prepared, do not silently generate PocketMine terrain in the requested additional world. Report the error; retry on a later start.
- Keep the world and its data on disk when the option is disabled again. Chunk generation follows normal demand / spawn preparation, not full-map pregeneration.

## Egg requirement

Use the Egg with the obsolete preflight check removed; beta.6 has no `VanillaWorldgenSetup.php` or `--prepare-vanilla-worldgen` command and should not be rejected at startup. The Egg also handles beta.6 safely with a warning when this optional feature is requested.

The RyzeVanillaGen executable stays external to the PHAR and is managed by `RyzeCompany/egg-ryzemp`. RyzeRTC remains the sole NetherNet native engine, sharing the configured public port with RakNet where applicable.

## Verification before publishing

The integration and extended GitHub Actions checks must pass on the exact merged `main` commit. Verify a clean server, an existing normal world, restarting with the option on/off, a name collision, a data fetch failure, and clients on Bedrock 1.26.40 / 1.26.60. This beta is not a declaration of production readiness.
