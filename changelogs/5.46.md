# 5.46.0
Released 17th October 2026.

This is a feature release for Minecraft: Bedrock Edition 1.26.52 (display version 26.52, protocol 2193). It replaces 5.45.0, which was withdrawn: see [5.45.md](5.45.md) for everything VanillaMine brought.

**Plugin compatibility:** Plugins for previous 5.x versions will run unchanged on this release, unless they use internal APIs, reflection, or packages like the `pocketmine\network\mcpe` or `pocketmine\data` namespace. The plugin API only gained additions.
Do not update plugin minimum API versions unless you need new features added in this release.

## Plugin compatibility
The 40 most downloaded API 5 plugins of Poggit were tested on VanillaMine and on PocketMine-MP 5.44.3: the ones that fail, fail the same way on both. Plugins that implement things VanillaMine now has keep working:
- A plugin registering an item alias VanillaMine added after 5.44.3 (e.g. `filled_map`, ImageOnMap) no longer fails to enable (which stopped the server): the built-in item is kept and a warning is logged.
- Mob plugins (e.g. Mobs) and VanillaMine's mobs coexist. VanillaMine's mobs now save under their `minecraft:` name, so a plugin registering the short names (`Creeper`, `Zombie`...) gets its own saved mobs back and ours load as ours; a plugin cannot take over the `minecraft:` names.
- The natural spawner counts the mobs of plugins in its population caps, so a plugin with its own spawning shares them instead of doubling the mobs.
- Mobs leave plugin NPCs alone: a living entity of a plugin class that has a name, stands still for clients (`setNoClientPredictions()`, e.g. Slapper) or is not saved (`setCanSaveWithChunk(false)`, e.g. Shopkeepers). Such NPCs do not count towards the population caps either (`mobs.ignore-plugin-npcs`, default on).

## API
Modelled on Paper:
- `pocketmine\entity\SpawnReason` and `Living::getSpawnReason()` / `setSpawnReason()`: why a mob came into the world (natural, structure, patrol, raid, spawn egg, spawner, breeding...), saved with the mob.
- `pocketmine\event\entity\MobPreSpawnEvent`: called before the natural spawner creates a mob; cancelling it is free. Mob plugins can turn off the server's natural spawning of some types.
- `pocketmine\event\entity\EntityTargetEvent`: called when a mob picks a new attack target; cancel or replace the target (e.g. NPC plugins).
- `StringToTParser::keepBuiltIn()` (`@internal`).

## Configuration
New in `pocketmine.yml` (the defaults keep the previous behaviour):
- `mobs.spawning.count-all-mobs-for-spawning` (default `true`): `false` counts only naturally spawned mobs towards the caps, like Paper's default.
- `mobs.spawning.spawn-limits.<animal|monster|ambient|water_animal|pillager>` (default `-1`, vanilla Bedrock caps).
- `mobs.ignore-plugin-npcs` (default `true`).

## Documentation
- The proxy is called VanillaGate: https://gitlab.com/VanillaPocketMine/VanillaGate

# 5.46.2
Released 18th October 2026.

This release cuts the memory of servers with the vanilla generator (2-3 GB on a Pterodactyl node without players before) and the main thread cost of crowded servers. Gameplay and generated worlds are unchanged (the performance changes are checked against the previous code by equivalence tests), and the plugin API only gained additions.

## Fixes
- Fixed a server crash in chunk generation (`PopulationTask` "Generator context should have been initialized") after an async worker had been shut down: when a worker with a higher ID was still running, the stopped worker was taken for a running one and got a population task without its world generator. The bug comes from PocketMine-MP, but the idle worker shutdown below made it reachable in normal play. The same check also built a second copy of the generator on a worker that already had one.
- Pterodactyl: the server no longer fails to start with "No space left on device". The phar's decompressed cache (~105-118 MB) did not fit the panel's 100 MB tmpfs `/tmp`; it is now ~25 MB and goes to `.tmp` on the server's disk (see below).
- The server no longer fails on every start when its temporary directory is missing, e.g. the Pterodactyl egg's `.tmp` deleted in the file manager or left out of a restored backup: the phar creates it again.

## Memory
A freshly started server used 2-3 GB of RAM on a Pterodactyl node without players: every async worker that generates vanilla terrain holds its own copy of the generator, and `settings.async-workers: auto` started one worker per core of the host (a container sees all of them), up to 14 on a 16-thread node. Worlds and generation are unchanged.
- `settings.async-workers: auto` counts only the cores the container may use, minus 2, and starts at least 2 and at most 4 workers. The cores are limited by the CPU limit (cgroup `cpu.max`, cgroup v1 CFS quota; read from the process's own cgroup when the container shares the host's cgroup namespace) and by CPU pinning (`cpuset.cpus.effective`, cgroup v1 `cpuset.effective_cpus`). A number set explicitly is used as before.
- Only 2 async workers generate chunks (`chunk-generation.max-workers`, `0` = all of them, as before); the others still run every other async task and stay small (~30-80 MB instead of ~135-165 MB). Measured with 4 workers: 795 -> 533 MB without players, 1000 -> 824 MB with one player, at about the same generation speed. Other async tasks (plugins, chunk sending, lighting) go to one of the other workers when it is running and idle, so they delay generation less (a long-running task can still hold a generation worker when the others are busy); no worker is started for this.
- Async workers without tasks for 300 s are shut down and started again when needed (`memory.async-worker-idle-timeout`, checked every minute and at the periodic garbage collection; `0` = only at the periodic garbage collection, after 300 s, as before). Previously idle workers were only stopped every 30 minutes. Low memory and `/gc` still shut down the workers idle for 300 s.
- A vanilla generator worker uses ~45 MB less: the decoded biome parameter files (~25 MB, `WorldgenData`) are no longer kept after building the biome trees, and the PHP material rules and carvers are only built when the native core is not used.
- The native terrain core (vanillagen) gives the memory of a generation burst back to the system after 30 s without requests.

## Configuration
- `network.compression-level` is `1` instead of `6` in new `pocketmine.yml` files (and when the value is invalid): compressing takes about half the time (level 6 cost 8.2 ms of main thread per tick with 200 players), movement batches come out the same size and chunks ~10-12% bigger. Existing `pocketmine.yml` files keep their level.
- New `chunk-generation.max-workers` (default `2`, `0` = all async workers).
- New `memory.async-worker-idle-timeout` (default `300` seconds, `0` = only at the periodic garbage collection).

## Performance
Measured with up to 200 players close together; same results as before. With 200 players (StressBots, 4 vCPU), main thread time per tick: -18% with players standing around and -7% with players exploring and changing dimension on the current PHP-Binaries build (chunkutils2 0.3.9); -26% and -15% with chunkutils2 0.3.10. chunkutils2 0.3.10 also stops keeping each player's largest packet batch in native memory for the whole session (~3.5 MB per player: 200 players used ~700 MB less), so update PHP-Binaries when a build with it is published.
- Movement broadcasts of players and mobs: the per-viewer distance loop is cheaper and the path is chosen before it. With chunkutils2 0.3.10, the viewer selection runs in C++ (`NativeSendBuffers::selectMovement()`, ~45-60 instead of ~130-150 ns per mover and viewer) and session send buffers are looked up by slot (`openNew()` ids), which speeds up every broadcast. With an older chunkutils2 (the current PHP-Binaries build ships 0.3.9) the PHP loop runs.
- Ground check: `Player::checkGroundState()`, the wall check ahead of players and the client-driven moves of mobs and boats test the cells under the feet first (`World::hasCollisionBlocks()`): ~0.7 instead of ~11-14 us when standing on the ground. The answer is the same as `getCollisionBlocks()`; only which blocks end up in the world's block cache differs (see its documentation).
- Fire: a fire skips its spreading step when no block within reach encourages flames (e.g. fires on netherrack in the Nether): ~2 ms per tick in a busy Nether. Burning the neighbouring blocks is unchanged.
- Players: the entity touch scan is skipped when every touched entity would ignore it, a chunk order that would change nothing is skipped, and map updates no longer clone every player's held items.
- Mobs and worlds: the AI's player distance checks (despawning, activation, targets, tempting, slime contact) read player positions without copies, enderman stare checks test the view cone first, target searches for a mob class are skipped in worlds without any (endermites, piglins, foxes, skeletons, wolves), and LevelDB chunk saves cache the NBT of block palette entries (byte-identical saves).

## Phar and Pterodactyl egg
- The decompressed cache of the phar leaves out the native programs (vanillagen, pm-nethernet) of every platform: ~25 MB instead of ~105-118 MB, written in ~0.2 s instead of ~2.2 s, and it keeps the phar's metadata (git commit, build number). The program for this platform is copied from the phar into the server's `bin` folder when it is missing or its size or modification time differ.
- On Linux, when `/tmp` is a tmpfs (RAM: Pterodactyl mounts a 100 MB one, counted as the server's memory) and neither `TMPDIR` nor `sys_temp_dir` is set, the phar puts its temporary files in `.tmp` next to it, and sets `TMPDIR` for the server and the programs it starts.
- The egg (`build/pterodactyl/egg-vanillamine.json`) has a new `PHP_JIT` variable (default `tracing`): the install script turns the PHP JIT on in `php.ini` (PHP-Binaries ships it off); existing servers get it on their next reinstall. `TMPDIR=/home/container/.tmp` is now a hidden variable and the startup command is the plain PocketMine one. Import the egg again to get these; the old one keeps working.

## API
- `AsyncPool::isWorkerRunning(int $workerId)`: whether a worker is running. `getRunningWorkers()` returns a list of IDs, which must not be indexed by worker ID.
- `AsyncPool::selectWorkerAmong(int $count)`: like `selectWorker()`, among the first `$count` workers only.
- `AsyncPool::setReservedWorkerCount(int $count)`: `selectWorker()` (and so `submitTask()`) prefers an idle running worker with an ID of at least `$count`.
- `AsyncPool::shutdownWorkersIdleFor(int $idleSeconds)`: like `shutdownUnusedWorkers()` (unchanged, 300 s) with another idle time.
- `AsyncGeneratorExecutor::setMaxWorkers(int $count)`: number of workers that generate chunks.
- `Server::MAX_AUTO_ASYNC_WORKERS`: the most workers `settings.async-workers: auto` starts (4).
- `Utils::getUsableCoreCount()`: `getCoreCount()` limited by the CPU quota and the CPU set of the process's Linux control group.
- `World::hasCollisionBlocks(AxisAlignedBB $bb)`: whether `getCollisionBlocks()` would return any block, without building them.
- `World::hasEntitiesOfClass(string $class)`: whether the world has an entity of that class (or a subclass).
- `NearestAttackableEntityGoal` and `NearestLivingTargetGoal`: optional last constructor parameter `$requiredClass`, the class the filter only accepts (the search is skipped in worlds without any).
- `WorldgenData::multiNoiseBiomes(string $dimension)`.
- `@internal`: `BundledBinary`, `Mob::getLiveLocationOf()`, `Mob::getLiveBoundingBoxOf()`, `SimpleInventory::isSlotInstanceOf()`, `NetworkBroadcastUtils::canAppendToNativeSendBuffers()`, `getNativeMovementSelector()`, `setNativeMovementSelectionEnabled()`, `broadcastPacketsToSendIds()`, `Utils::parseCgroupCpuLimit()`, `parseCgroupCpuList()`, `parseCgroupV2Path()`. `NetworkSession::getSendId()` returns ids from chunkutils2 when it has `openNew()`.

# 5.46.3
Released 18th October 2026.

This release fixes packets that had the wrong layout for Minecraft 1.26.40/1.26.50 (protocol 2193). Every packet was checked: the ones the server sends in the bot tests, a filled sample of every packet against gophertunnel, the list of packets CloudburstMC changed after 1.26.30, Mojang's 1.26.51 protocol documentation, and packets captured from the official server (BDS 1.26.52), which now decode and encode back byte for byte. The plugin API only gained additions.

## Fixes
- Scoreboards work again (ScoreHud and other scoreboard plugins): `SetScorePacket` and `SetScoreboardIdentityPacket` use the 1.26.40 layout. Verified with the ScoreHud plugin and against BDS.
- `StartGamePacket`: integer game rules are written like in `GameRulesChangedPacket` (a plugin adding one broke joining).
- Sub-chunks (`SubChunkPacket`), player locations (`PlayerLocationPacket`), entity property overrides (`PlayerUpdateEntityOverridesPacket`), sound updates (`ClientboundUpdateSoundDataPacket`), camera presets (`applyInheritedStartingRotation`), custom camera splines (`CameraSplinePacket`), attribute layers (noise alignment; the Nether and the End were sent as other dimensions), structure blocks (redstone save mode), server presence, debug text (line gap) and the client's party and diagnostics packets use the new layouts.

## API
- `ClientboundUpdateSoundDataPacket::createUpdates()` and `SoundDataUpdate` (stop, volume, pitch, fade, seek, pause, resume); `create(int, string)` is kept but its sound event name is no longer sent.
- `PartyChangedPacket::createNoParty()` / `isInParty()`, `ServerboundDiagnosticsPacket::getSystemCategories()` (`SystemCategory`), `AttributeEnvironment::getNoiseAlignmentType()` / `getNoiseAlignmentValue()`, `PrimitiveShapeTextPayload::getLineGapHeight()`, `ScorePacketEntry::TYPE_REMOVE`.

# 5.46.5
Released 19th October 2026.

## Fixes
- Players with a persona skin (made in the character creator, including the default Steve and Alex) no longer show black eyes to the other players: the unused persona tint colours (`#0`) were sent as opaque black instead of transparent, and the black layer covered the whites of the eyes (and darkened hair and mouth). Persona pieces with compound names (beards, face accessories, separate arms and legs) get their tint colours too. The fix is in BedrockProtocol.
- Skins are sent to the other players exactly as the client sent them also after an in-game skin change and on NPCs that wear a player's skin (the same `Skin` object): persona skins are no longer replaced by a random colour there, and blinking eyes, slim arms and skin colour are kept. Skins made by plugins are converted as before. The player list shows the new skin after a skin change instead of the one from the login.

## Gameplay
- New `/gamerule` command (Bedrock syntax): `/gamerule` lists the rules of your world, `/gamerule <rule>` shows one, `/gamerule <rule> <value>` changes it; an optional last argument names another loaded world (the console uses the default world). Permission `pocketmine.command.gamerule` (operators). Each world saves its rules in its `level.dat`, like vanilla Bedrock, so worlds made with Minecraft keep theirs.
- Supported rules: `dodaylightcycle`, `doweathercycle`, `domobspawning`, `doinsomnia` (phantoms), `dopatrolspawning`, `dotraderspawning`, `dofiretick` (fire neither spreads nor burns out), `domobloot`, `dotiledrops`, `doimmediaterespawn`, `keepinventory` (items and experience), `naturalregeneration`, `mobgriefing` (explosions of mobs leave blocks alone), `tntexplodes`, `pvp`, `falldamage`, `firedamage`, `drowningdamage`, `freezedamage`, `showcoordinates`, `showdaysplayed`, `showdeathmessages` and `randomtickspeed` (multiplies `chunk-ticking.blocks-per-subchunk-per-tick`). The client is told about the rules it shows itself (coordinates, days played, sun and moon, respawn screen).
- The rules only set the default outcome: plugins still get the events (deaths, damage, block breaking, explosions) and can change the result.

## Configuration
- New `mobs.disabled-worlds` in `pocketmine.yml` (default `[]`): worlds (folder names) without mobs, like `mobs.enabled: false` but only in those worlds (no AI, no natural spawning, patrols or raids). To only stop natural spawning in a world, use `/gamerule domobspawning false` there.

## API
- `World::getGameRule()`, `getGameRules()`, `setGameRule()`, `areMobsEnabled()`; `pocketmine\world\GameRules` (names and defaults); `pocketmine\event\world\WorldGameRuleChangeEvent` (cancellable, the value can be replaced); `pocketmine\world\format\io\GameRulesWorldData` (implemented by `BedrockWorldData`). `NetworkSession::syncWorldGameRules()` and `getClientGameRules()`.

# 5.46.6
Released 24th October 2026.

## Fixes
- Servers no longer crash with "malformed SubChunk" while saving or sending chunks. After a subchunk dropped its empty block layers, the layer list could be left in a state the native chunk serializer of chunkutils2 0.3.8 and newer (the PHP-Binaries release ships 0.3.9) could not read, which stopped the server. The layers are now dropped without leaving it in that state; nothing else changes.
- Villagers whose bed or job site has a negative coordinate no longer crash the server after a chunk reload (a negative Y threw "Y coordinate out of range"), and negative X/Z positions are no longer read back wrong. Creakings no longer lose the creaking heart that summoned them when it is at a negative coordinate. Saved worlds load unchanged: the saved data is the same, it was only read back wrong.
- Real players are no longer kicked with only "Client disconnected" when a bot or a fake player of a plugin joins. The 1.26.52 client disconnects when the player list gives another player a device type it no longer knows (the old Windows 10 UWP, Gear VR, HoloLens, tvOS and Windows Phone values); such values are now sent as "unknown".
