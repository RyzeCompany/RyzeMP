# 5.48.0
Released 27th October 2026.

**Recommended PHP binaries: [php-8.4-20261026](https://gitlab.com/VanillaPocketMine/PHP-Binaries/-/releases/php-8.4-20261026)** (chunkutils2 0.3.15), the same as 5.47.

This is a support release for Minecraft: Bedrock Edition 1.26.60 (display version 26.60, protocol 2225). Only 1.26.60 clients can join: 1.26.52 clients can't, and 1.26.60 clients can't join older servers. Plugins for previous 5.x versions run unchanged: the plugin API only gained additions.

It also includes everything done since 5.47.0 (there was no 5.47.1 release): spectator head flicker, ender pearls hanging in mid-air outside the simulation distance, blank maps after rejoining, the async worker memory limit, faster joins and the new NetherNet bridge (below).

## Faster joins
- Players get into the world much sooner (measured with bots and simulated latency: 6.9 s to 4.1 s for the first join after a start, 4.4 s to 3.1 s after idle). The spawn chunks are loaded and encoded while the client is still logging in and sent in a burst before spawning (a 10 ms per-tick budget shared by joining players, never fewer than the usual 4 chunks per tick); chunk encoding stays on a worker that already has the block palette, and one is warmed up during the login; the packet pool, entity factory and Minecraft auth keys are prepared at startup instead of on the first join.
- `chunk-sending.fast-spawn` in pocketmine.yml (on by default). About 12 MB more right after startup, less once players join (only one worker holds the palette). Gameplay CPU is unchanged: all of it runs before a player spawns.
- API additions: `AsyncPool::getReservedWorkerCount()`, `AuthKeyProvider::prefetch()`.

## Fixes
- A block changed while its chunk was being prepared for sending was lost for the players waiting for that chunk (they saw the old block, e.g. air where there was water). The chunk is now prepared again before it is sent (an old upstream FIXME).
- Attack and interaction reach is measured to the nearest point of the entity's bounding box instead of its feet, so big entities (the ender dragon's wings) can be hit away from their centre.

## Network
- Protocol 2225. Changed packets: the player list carries the PlayFab ID (no longer in the skin), AddActor/AddPlayer can say which block an entity rides, Animate and the release/use-on-entity transactions say which hand, LevelChunk, StartGame (editor level migration version), dimension data (cloud height, render clouds), ClientboundUpdateSoundData (one tagged event), crafting requests (a new reserved action renumbers the two deprecated ones). New packets 353-360 (matchmaking state and cancel, stonecutter recipe selection, riding blocks, cursor item drag, audio content).
- Checked against the released Bedrock Dedicated Server 1.26.60.6: every packet it sent in scripted sessions (a plain world and one with the Drop 4 experiment) decodes and encodes back byte for byte (the captures are now BedrockProtocol tests). Fixed on the way: LevelChunk in sub-chunk request mode wrote the request limit as the sub-chunk count, and LegacyTelemetryEvent left its event data unread. The item list, entity identifiers and jigsaw data are identical to BDS; the biome definitions now carry the tags BDS sends (abandoned camps, oak forest, temperate oceans) and two values that were rounded. Worlds are stamped as last opened in 1.26.60.6.
- 1.26.60 clients only connect with NetherNet (they refuse RakNet-only servers with "unsupported transport"). NetherNet is on by default (`enable-nethernet`); the server port must be open in TCP and UDP. RakNet stays on for Query and tools. iOS clients only try HTTPS for NetherNet signalling and refuse self-signed certificates (Mojang bugs BDS-23108 and BDS-23125, not fixed in 26.60, also with Bedrock Dedicated Server). **For iOS players, turn on HTTPS:** set `network.nethernet.https.acme-domains` in pocketmine.yml to the domain (or public IP) players type, and open TCP port 443 or 80 so Let's Encrypt can issue the certificate (checked with an iPhone on 26.60). Windows and Android join without it.
- The pm-nethernet bridge now comes from its own repository, [VanillaPocketMine/nethernet](https://gitlab.com/VanillaPocketMine/nethernet) (MIT), version 0.1.1 (the phar ships it as before). It batches the packets it passes to the server (2 ms) and caps what a client may leave unacknowledged (32 MiB): with 100 NetherNet players, 10% less CPU in total and bridge memory 156 to 130 MB, for 0.5-1.5 ms more median latency. `PM_NETHERNET_LINK_COALESCE=0` turns the batching off.

## Blocks
- 1.26.60 turned three visual shapes into block states that the client no longer works out by itself, so the server computes and stores them:
  - Redstone dust: the side/up/none connection of each side, with the vanilla rules (climbing a block to reach dust on top unless a conductor covers this dust, components, dust one block lower; a single connection extends into a line, none is a cross).
  - Fire: the sides and ceiling it clings to when it doesn't stand on a full or flammable block, kept up to date when blocks around it change and whatever places it (flint and steel, fire charges, dispensers, fireballs, lightning, lava, spreading).
  - Chorus plants: the connections of all six faces.
  Worlds saved before load without the shapes and get them when something changes next to the block. The vanilla generator gives the chorus plants, fire and redstone dust it places (End islands, structures) the shapes of the Java data.
- Red and brown mushrooms are placed (and stay) on any block with a solid top face or a central support (fences, walls) whatever the light, like 1.26.60: placing one in bright light no longer leaves a ghost block. Spreading still needs light below 13 unless the block below is mycelium, podzol or nylium.
- New block and item ids of 1.26.60 (disc press, icicle, ice crystal, frostbite spawn egg; the experimental Drop 4 content is only mapped, not available in creative or crafting).

## API
- `RedstoneWire::getConnection()` / `setConnection()` with the `pocketmine\block\utils\RedstoneWireConnection` enum; `Fire::hasConnection()` / `setConnection()` and `Fire::refreshShapeAt()`; `ChorusPlant::hasConnection()` / `setConnection()`.
- `EffectIds::FREEZING` (38) and `BiomeIds::ICE_CAVES` (196): ids of the experimental Drop 4 freezing effect and ice caves biome, checked on BDS 1.26.60.6. Neither is implemented yet.
- BedrockProtocol: the new packets and fields above; `LegacyTelemetryEventPacket::$rawEventData`.

# 5.48.1
Released 27th October 2026.

## Fixes
- Kicked players see the client's "kicked" disconnection screen with the kick message, like on Bedrock Dedicated Server, instead of "an error occurred": `Player::kick()` sends the disconnect reason code BDS uses for `/kick`. Other disconnections are unchanged.
- `/transferserver` refuses a port outside 0-65535 instead of truncating it (70000 sent the player to port 4464).

## Network
- Checked against Bedrock Dedicated Server 1.26.60.6: the transfer (`@minecraft/server-admin` `transferPlayer`, by address and port and by NetherNet ID), kick, dimension change, death and login packets BDS sends decode and encode back byte for byte, and VanillaMine's transfer packet is laid out like BDS's (reload world off, no gatherings data). The captures are BedrockProtocol tests now.
- Transfers on 1.26.60: clients only join over NetherNet, so `Player::transfer()` and `/transferserver` must point at a server that accepts NetherNet on that port (TCP for signalling and UDP), such as VanillaMine 5.48 or BDS with `transport=nethernet`. A RakNet-only destination (older PocketMine-MP, RakNet proxies) makes the transfer fail on the client. iOS players also need HTTPS on the destination (`network.nethernet.https`).
- pm-nethernet: a session the server closes now stays open until the client has acknowledged the last packets (at most 5 s) instead of a fixed 0.5 s. On a link with some loss the transfer or disconnect packet was sometimes lost and the player got "connection lost" instead of joining the other server. The bridge is now [nethernet 0.1.2](https://gitlab.com/VanillaPocketMine/nethernet/-/releases/v0.1.2).

## API
- `NetworkSession::onPlayerDestroyed()` takes an optional disconnect reason code. BedrockProtocol: `DisconnectFailReason` constants (protocol 2225).

# 5.48.2
Released 29th October 2026.

**Recommended PHP binaries: [php-8.4-20261026](https://gitlab.com/VanillaPocketMine/PHP-Binaries/-/releases/php-8.4-20261026)** (chunkutils2 0.3.15), the same as 5.47 and 5.48.0.

This release brings gameplay closer to Bedrock Dedicated Server 1.26.60. Most of the fixes below were found by VanillaBot, a test bot that plays the same scripted scenarios on VanillaMine and on BDS and compares the results: 98% of its 299 scenarios now behave the same, the rest are random on BDS or accepted edition differences. It also adds the Bedrock `/execute`, `/setblock`, `/fill`, `/summon`, `/replaceitem`, `/ride` and `/damage` commands, connection flood limits, a faster NetherNet link and makes plugins harder to crash the server with. Plugins for previous 5.x versions run unchanged: the plugin API only gained additions. Every change was benchmarked with 100 bots before it went in, and none costs extra CPU or memory.

## Plugin robustness
- A sleeper notifier callback that throws (plugins and virions use them for database and HTTP results, e.g. libasynql answering after the player quit) no longer takes the whole server down: like event handlers and form handlers, the failure is blamed on the plugin, logged, and counts towards disabling it (`plugins.crash-on-unhandled-exception` restores the old behaviour). Failures of core notifiers still crash the server as before.
- `Player::sendMessage()`, `sendTip()`, `sendPopup()`, `sendActionBarMessage()`, `sendJukeboxPopup()`, `sendTitle()`, `sendSubTitle()`, `setTitleDuration()`, `removeTitles()`, `resetTitles()`, `sendToastNotification()`, `sendForm()` and `closeAllForms()` do nothing (one debug line) on a player that already quit and was destroyed, instead of throwing from `getNetworkSession()` on every call; `transfer()` returns false. HUD and scoreboard tasks that keep the Player object no longer error every tick. `getNetworkSession()` itself is unchanged.
- An invalid form response (FormValidationException) is logged as one notice line without stack trace, at most every 5 seconds per player (the rest at debug), instead of a critical with a full trace for each response a client sends.
- `Entity::teleport()` returns false for NaN/infinite coordinates or rotations and for X/Z beyond the 32-bit block range, instead of throwing (or, for huge finite values, looking up chunks whose hashes wrap onto other chunks). `/tp`, `/spawnpoint`, `/setworldspawn` and `/particle` reject coordinates and rotations that are not finite (a few hundred digits are infinite as a float; as local `^` coordinates they became NaN, and `/tp ^999…9 ^ ^` crashed the server).

## Players
- Breaking a block in survival could kick the player with "Invalid raw value 4 for TriggerType": the item interaction in PlayerAuthInputPacket has a presence byte before its changed slots (like InventoryTransactionPacket since 1.26.50), which was skipped when the legacy request ID was 0 (BedrockProtocol).
- Breaking a block no longer makes the server reject the player's whole input packet for that tick (the client adds a block break prediction to it); the tool damage it predicts is now checked after the break.
- A player killed after its data was saved on quit (a hit in the same tick it disconnected, or while it waits to be despawned) dropped its inventory and experience although they were already saved: on rejoin it had them again, a duplication. Such a death no longer drops anything.
- The experience bar filled along the level curve instead of by points: 2 points at level 0 showed 0.317 of the bar (2.2 points) instead of 2/7, so smelting, mob and bottle experience looked fractional and higher than on BDS. `ExperienceUtils::getLevelFromXp()` now returns the level plus points / points of that level, and `ExperienceManager::getRemainderXp()` no longer loses a point to float rounding.
- `/xp -<n>L` with more levels than the player has also empties the bar, like vanilla (it kept the progress of level 0).
- Players are sent their exact health, like BDS 1.26.60: a 2.5-damage hit shows 17.5 (a half heart less) instead of being rounded up to 18.
- A player who joined after another player saw them 1.62 blocks lower until they moved: AddPlayer carried the feet position instead of the eyes like MovePlayer and BDS.
- Players' arm swings reach other players as an Animate packet like on BDS (mobs keep the actor event BDS uses for them).
- A player sending a bad packet is disconnected alone, like on BDS. Their address was also blocked for 5 seconds: on NetherNet that closed every player of that address at once (a proxy, carrier-grade NAT), and on RakNet the backlog the others sent when the block ended counted as a flood and blocked the address for 300 seconds. RakNet's automatic blocks (packet flood, malformed datagrams) now never apply to loopback addresses or to `network.connection-limits.exempt-addresses`; `/ban-ip` still does.
- Falls right after a teleport did 1 more damage than vanilla (4 instead of 3 for 6 blocks, 1 for 3 blocks): the client's 0.001 position offset no longer counts as fall distance.
- Sleeping players lie in the middle of the bed like on BDS (eyes 0.90625 above the bed block, for themselves and others), stay there until they wake up and get up beside the bed. A player quitting while asleep is saved standing. A sleeping player also has the generic sleeping entity flag, like on BDS.
- Respawning away from a missing or obstructed bed sends no message, like BDS (it sent "Your home bed was missing or obstructed"). Respawn anchors keep theirs.
- `/effect` with instant health or instant damage applies it once, like vanilla, instead of every tick for the given seconds (`/effect @s instant_damage 1 1` killed instead of taking 12 health, so a player then killed by a mob got the magic death message).
- Offline (self-signed) logins no longer log two "Unexpected JSON property" warnings per join for the ipt and tid claims.

## Combat and explosions
- Melee hits round the weapon damage plus the enchantment bonus down to a whole number, like Bedrock (an iron sword with Sharpness V does 13, not 13.25). Strength (x1.3 + 1 per level) and Weakness (x0.8 - 0.5 per level) use the Bedrock formula on player hits, and the mace smash bonus counts before Strength and the critical hit (a 2.7-block smash does 25.2 like BDS, not 19.8). Measured against BDS 1.26.60.
- Zombies, husks, drowned, zombie villagers, zombified piglins and evokers have 2 points of natural armor like on BDS, and armor is capped at 20 points (natural plus worn).
- Mobs holding a weapon (vindicators, piglin brutes, wither skeletons, zombified piglins, zombies given a sword...) add its damage to their attack before the difficulty scaling, like BDS: on Easy a vindicator hits 7.5 instead of 5 and a wither skeleton 5.5 instead of 3. The bonus is the item's attack damage without the fist's 1 point.
- A melee mob's first hit waits one whole attack interval after it starts attacking, like BDS 1.26.60: zombies first hit a player next to them after about 1.1 s and hoglins after about 2.3 s, where they hit at once. Two hoglins killed a player feeding them in 5 seconds instead of 10, so breeding hoglins by hand rarely worked.
- Explosion exposure is traced from the entity to the blast like vanilla: an entity standing on the same floor as the explosion counted as a quarter hidden (less damage, less shield wear). A block the ray only touches at one of its ends (the floor under a creeper's blast) doesn't hide the entity either.
- A raised shield blocks explosions from any side, like on BDS (it only blocked blasts in front).
- TNT explodes from near its bottom like vanilla instead of its middle: it broke about 30% more blocks than BDS and Java.
- Primed TNT drifts in flowing water like BDS 1.26.60: on the ground it keeps 0.7 of its speed whatever the block (not the block's friction), and currents push it twice as hard as other entities, so a water TNT cannon throws its projectile about 6 blocks (BDS 7-8) instead of 2-3. Primed TNT slid about 0.02 blocks per tick down a stream, BDS about 0.09.
- Falling stalactites hurt by their length per block fallen, like BDS 1.26.60 (a 2-block stalactite falling 3 blocks does 4, at most 40); they did at least 6 per block like Java.
- Thrown and shot projectiles no longer send a motion update every tick while they fly on their own: clients simulate the flight from the spawn motion like on BDS (one packet less per projectile per tick; a thrown trident showed gravity already applied).

## Mobs
- The body of a dead mob stayed where it died for the whole death animation. Like on BDS 1.26.60, the killing blow now knocks it back (about 2 blocks for a sword hit, like the earlier hits) and a mob dying in the air falls. Only bodies that still move are updated, for at most the 25 ticks of the animation.
- Slimes and magma cubes split when the body disappears at the end of the death animation, where it slid to, like vanilla (they split the moment they died, so the small slimes had already hopped off by then). The small slimes appear above the dead slime's centre and, like slimes, magma cubes and sulfur cubes, wait their normal jump delay before their first hop, like BDS 1.26.60: they hopped at once after the player and were 4-8 blocks away a second later (BDS: first hop 11-14 ticks after spawning, 1-3 blocks away). Hops in water and lava still start at once.
- Animals in love look for a partner up to 20 blocks away, like BDS 1.26.60 (19.8 blocks still worked there, 21.2 didn't), instead of 8. Two foxes fed by a player run away from them in opposite directions and often ended up 10-14 blocks apart, so they never bred.
- Zombies, husks and drowned notice players up to 35 blocks away (28 while sneaking), like BDS 1.26.60, not 25.
- Mobs that don't walk through fire (vindicators and others) go through a line of fire when there is no way around it, like on BDS 1.26.60 and Java: fire costs 16 in their paths instead of being a wall, and they still take a gap when there is one. Husks and zombies no longer stop in front of fire with chunkutils2 older than 0.3.11.
- A guardian with a target holds its depth instead of sinking, like vanilla and BDS 1.26.60: one summoned in a 3-deep pool sank to the bottom while charging, lost sight of the player at the pool edge behind the basin and never hit (BDS hits after about 4.5 s).
- Mobs send their health to viewers when it changes, like BDS, so the health bar of a ridden horse or camel follows damage and healing.
- A rolled up armadillo stops moving (movement 0) and has the timer and blocked body rotation flags BDS sets, so clients show it rolled up when hit.
- Harvesting a full beehive or bee nest with shears or a bottle without a campfire below also angers the bees around it (within 8 blocks, 6 up and down), like on BDS, not only the bees inside.
- In the Nether and the End, natural spawning treats a chunk biome of another dimension (old worlds, other generators) as the dimension's default biome, so zombies and creepers can't spawn there.
- Trade offers are sent without the Hero of the Village discount, which the Bedrock client applies itself (it was applied twice, BDS sends the base price).
- The raid bar titles are the ones BDS 1.26.60 sends, as translation keys so each client shows them in its language: `raid.name` while preparing and fighting, `%raid.name - %raid.progress N` with fewer than 3 raiders left ("Mobs remaining: N"), `%raid.victory` and `%raid.defeat`, instead of `%raid.name` and an English "Raiders Remaining".

## The End
- The End fight (exit portal frame, pillar crystals, dragon and its boss bar) also starts for players who are in the End without having come through an End portal: logged in there, or brought by `/tp`, `/execute in` or a plugin. It only started on End portal arrival, so such an End had no dragon.
- Only the ender dragon of the End fight opens the exit portal, drops the egg and spawns a gateway when it dies; a summoned dragon doesn't, like on BDS. Dragons saved before this count as the fight's while a fight is on.
- A dying ender dragon stays where it died during its death animation, like BDS 1.26.60, so its experience falls there. It flew above the exit portal and rose, and once the portal was open most of the orbs fell into it and went to the Overworld: a player standing by the dragon often got almost no experience.
- A dying ender dragon sends the death event (ActorEvent 3) and then the dragon death event (37) on the next tick, and keeps its boss bar at 0% until it is removed, like BDS 1.26.60 (it sent only 37 and hid the bar at once).

## Blocks, items and crafting
- Special crafting recipes the client hardcodes (shield decoration, banner copying, maps, firework stars and rockets, armor dyeing...) were refused in a crafting table: they were matched against the player's empty 2x2 grid instead of the table's.
- Enchanting in an enchanting table was refused for Bedrock clients: the request consumes the item and places the enchanted one back into the same slot, which the client names by stack ID 0 once emptied, and the server compared it with the ID from before the request.
- The enchanting table clears its offers when the item can't be enchanted or is taken out (they stayed on screen), and items nothing can be put on (a stick) get no offers.
- Blaze powder put in a brewing stand fills the fuel bar at once, like vanilla, not only once something can be brewed.
- Bone meal used on a fungus planted on the other nylium is consumed without growing it, like on BDS.
- An observer ignores changes it sees while pulsing (or waiting to pulse) like vanilla and BDS 1.26.60: two observers facing each other pulse every 6 ticks (one 2 ticks after the other), not every 4. Observer chains and the 2-tick pulse are unchanged.
- Minecarts on a rail are sent 0.4375 above their bottom instead of 0.35, like BDS 1.26.60 (rail.y + 0.5 on a flat rail, rail.y + 1.5 - d along a slope); off the rails they keep 0.35, which BDS also uses there.
- Water evaporating in the Nether (an emptied bucket, melted ice) plays the "fizz" sound event like BDS instead of the fizz level event, which Bedrock clients don't play there.

## Worlds
- Loot tables work on every server, whatever the world generator: when no vanilla world prepared the vanilla data, the server downloads Mojang's official server.jar once in the background at startup (about 60 MB, nothing waits for it) and keeps only the loot tables (about 2 MB in `vanilla-worldgen/`). Vaults, trial spawners, decorated pots, suspicious sand and gravel and loot chests then roll their loot without a restart. `loot-tables.auto-download` in pocketmine.yml turns the download off; a loot table that can't roll logs one warning saying why (it was a debug line).
- A world loaded as an Overworld that looks like a Nether or End (name ending in `_nether`/`_the_end`, or a spawn in the hell or the_end biome) logs a warning with the `worlds: <name>: dimension:` setting to fix it. It isn't changed automatically: the dimension also sets the height limits.
- `/locate biome` in vanilla worlds reports the surface height of the column found, like BDS 1.26.60 (plains at 69, taiga at 64 for seed 1001, the same as BDS), instead of the height it searched at (always 86 for a player standing at 86).

## Other
- The startup message links to docs.vanillamine.com and plugins.vanillamine.com instead of the PocketMine-MP documentation and Poggit.
- The repository has VanillaMine CONTRIBUTING and SECURITY files and GitLab issue and merge request templates.

## Flood protection
Connection limits against UDP and join floods, under `network.connection-limits` in pocketmine.yml (0 turns a limit off). They are generous on purpose: players on slow or lossy links need several seconds to join, and many players can share one address (mobile carriers, schools, LAN parties). Players who are already in the game are never disconnected by them; only new joins are refused while a limit is reached, with at most one debug line per 5 seconds.
- `pending-logins-per-ip` (32): connections from one address (IPv6: /64) that have not logged in yet, RakNet and NetherNet. `exempt-addresses` lists trusted proxies (IPs or CIDR) that the per-address limits skip.
- `raknet-pongs-per-second` (1000): a global cap on RakNet server list replies, against spoofed-ping reflection.
- `nethernet-pending-joins` (256), `nethernet-pending-joins-per-ip` (32), `nethernet-max-connections` (2048), `nethernet-max-connections-per-ip` (off), `nethernet-max-buffered-mb` (1024) and `query-per-second` (200): limits of the pm-nethernet bridge. They are passed in its environment, so pm-nethernet 0.1.2 ignores them; the next pm-nethernet release applies them.
- RakLib counted the packets of an address within a single tick and blocked the address for 5 minutes above 200. When the server was late, everything waiting in the socket was read at once and players sharing one address were all disconnected. The limit now applies to the average over one second.
- Sessions that disconnected before logging in stayed in the pending list forever; they are now forgotten.

## Network
- NetherNet: the link between the server and the pm-nethernet bridge uses a Unix socket when the bridge supports it (link version 2, the next pm-nethernet release) and falls back to loopback TCP otherwise, so pm-nethernet 0.1.2 and older keep working. The link thread hands the received data to the main thread in one piece per read instead of one entry per frame, and outgoing packets are framed with a single copy. Measured with 100 NetherNet clients (4 interleaved runs each, against 5.48.1 with pm-nethernet 0.1.2): 4.6% less CPU for the server and the bridge together (other server threads -16%, bridge -6%), bridge memory 130 to 101 MB, chat round trip unchanged (median 40.6 to 39.4 ms, p95 71.8 to 71.4 ms). `PM_NETHERNET_LINK=tcp` keeps the link on TCP.

## Commands
- `/execute` with the Bedrock syntax: as, at, positioned, rotated, facing, align, anchored, in <dimension>, if/unless block|blocks|entity, run (no `if score` yet).
- `/setblock` and `/fill` with the Bedrock syntax and block states (`["state"=value]`), also for blocks newer than the legacy ID tables (soul soil, vaults, copper...). Like BDS they only change the main layer (a waterloggable block set in water keeps the water), place both halves of doors and tall plants, and keep the thickness given to pointed dripstone. `/fill` has replace, destroy, keep, hollow, outline and `replace <block>`, up to 32768 blocks.
- `/summon` with all Bedrock overloads, spawn events (slime sizes, charged creeper, babies and adults, villager professions) and name tags; `/summon lightning_bolt` strikes like natural lightning (plugins see it in LightningStrikeEvent); `minecraft:on_tame` tames horses, donkeys, mules, llamas, wolves, cats and parrots for the player who summons them.
- `/replaceitem` for entity slots (hands, armor, hotbar, inventory, ender chest) and block containers, with destroy and keep.
- `/ride` (start_riding, stop_riding, evict_riders, summon_rider, summon_ride) and `/damage` (Bedrock damage causes, optional damager).
- Selectors: `type=villager` and `type=zombie_villager` also select the current villagers and zombie villagers, like BDS.
- API additions: `ExecuteCommandSender`, `CommandFailureException`, `CommandBlockParser`, `ParsedBlock`, `CommandBlockWriter`, `CommandItemParser::applyTags()`, `CommandParameter::block()` and `blockStates()`, `CommandEnums::BLOCK`, `CommandParameterType::BLOCK_STATES`, protected `VanillaCommand` helpers. New op permissions `pocketmine.command.damage`, `.execute`, `.fill`, `.replaceitem`, `.ride`, `.setblock`, `.summon`.

## API
- Additions only: `Player::getActiveCraftingGrid()`, `CombatRules::getMeleeWeaponDamage()`, `applyStrength()`, `applyWeakness()` and `MAX_ARMOR_POINTS`, `EnderDragon::isFightDragon()` / `setFightDragon()`, `AbstractMinecart::NETWORK_Y_OFFSET_ON_RAILS`, `NavigationOptions::FIRE_COST`, `AddressSet` and the pending login limits of `NetworkSessionManager`, and the command classes listed under Commands.
- Behaviour changes: `ExperienceUtils::getLevelFromXp()` returns the progress by points (see Players); `BreedGoal` searches 20 blocks for a partner.
- BedrockProtocol: the item interaction data of PlayerAuthInputPacket reads and writes the presence byte of its changed slots.

# 5.48.3
Released 31st October 2026.

**Recommended PHP binaries: [php-8.4-20261026](https://gitlab.com/VanillaPocketMine/PHP-Binaries/-/releases/php-8.4-20261026)** (chunkutils2 0.3.15), the same as 5.48.2.

A bug fix release. Plugins for previous 5.x versions run unchanged: the plugin API only gained additions.

## Fixes
- The server crashed when a Slowness effect of level 7 or higher ran out (for example `/effect @s slowness 5 255`): removing it divided the movement speed by a negative factor. Sprinting, Speed and Slowness are now multipliers of the base movement speed, worked out again each time like vanilla's attribute modifiers, so they can be added and removed in any order without drift, and a base speed changed while they are active (a baby mob growing up, a plugin calling `setMovementSpeed()`) keeps them.
- A shield raised by using it was lowered after its first block, and the next hit landed in full: writing the shield's wear back to the hand stopped the use of the item. This affected Java players (who always raise the shield by using it) and Bedrock players using it from the main hand. Like vanilla, using an item (a shield, food, a bow, a trident) now only stops when the hand holds another kind of item, not when the same item only wears or changes NBT.
- Removed `lcg_value()` and `curl_close()`, deprecated in PHP 8.4 and 8.5: the End dragon fight and the vanilla data downloads no longer log deprecation notices.

## API
- Additions only: `Living::getBaseMovementSpeed()`, `Living::setMovementSpeedMultiplier()` (internal), and the `Living::SPEED_MODIFIER_*` and `Living::SPRINT_SPEED_MULTIPLIER` constants.
- `Living::setMovementSpeed()` sets the base speed; the attribute value is the base speed times the active multipliers. `getMovementSpeed()` still returns the current (multiplied) value. A movement speed attribute value set directly by a plugin becomes the new base speed.

# 5.48.4
Released 31st October 2026.

**Recommended PHP binaries: [php-8.4-20261026](https://gitlab.com/VanillaPocketMine/PHP-Binaries/-/releases/php-8.4-20261026)** (chunkutils2 0.3.15), the same as 5.48.3.

A PvP release. Plugins for previous 5.x versions run unchanged: the plugin API only gained additions.

Highlights:
- **Knockback is PocketMine-MP's again by default**, for Bedrock and Java players alike, and the knockback, vertical limit and attack cooldown that plugins set are kept as they are. Servers that want the vanilla knockback of 5.45 to 5.48.3 set `player.knockback: vanilla` in pocketmine.yml.
- **Damage like BDS 1.26.60**: Bedrock Protection enchantments, critical arrows (they never were before) and crossbows loaded on release.
- The known differences from BDS (reach, sprint knockback, main-hand shield) are listed at the end of Combat.

## Combat
- Knockback of players' melee hits is like PocketMine-MP 5.44.3 again by default, for Bedrock and Java players: a 0.4 push capped at 0.4 up, the Knockback enchantment as a second push, no extra push for a sprinting attacker, and armour doesn't resist knockback. The vanilla knockback of 5.45 to 5.48.3 (a sprint hit pushes one Knockback level further, in the same push as the enchantment; each netherite armour piece resists 10%) is now the option `player.knockback: vanilla` in pocketmine.yml (`pmmp` is the default).
- In both modes, the knockback, vertical limit and attack cooldown a plugin sets on `EntityDamageByEntityEvent` are applied as they are, like on PocketMine-MP 5.44.3: no sprint push on top, and the pushes some mobs add to their hit (iron golem and hoglin/zoglin toss, drowned pushing swimmers down, goat ram, warden sonic boom) are left out when a plugin changed the hit's knockback. A cancelled hit pushes nothing.
- Protection enchantments work like Bedrock: 1 point per level for Protection, 2 for Fire, Blast and Projectile Protection, 3 for Feather Falling, 4% less damage per point up to 20 points, without the random part of the old Java formula (full diamond armour with Protection IV took an iron sword's hit down to anywhere from 0.38 to 1.13 at random; BDS 1.26.60 and now VanillaMine: always 0.68).
- Arrows were never critical: the critical flag was cleared before the damage of the hit was worked out, so a fully drawn bow did 6 and a crossbow 7. A critical arrow (a full bow shot, every crossbow bolt) now adds a random amount up to half the damage plus 2, not rounded, like BDS (bow 6 to 11, crossbow 7 to 12.5 at short range).
- A crossbow released after a full charge is loaded, like on BDS, not only when the client reports the end of the charge.
- Checked with VanillaBot against BDS 1.26.60 player against player: weapon damage, Sharpness/Smite/Fire Aspect, critical hits, the invulnerable ticks (a stronger hit does the difference), armour and Protection, bow/crossbow/trident and death messages behave the same. Java players through VanillaBridge (Java against Java, Java against Bedrock, and Java 1.21.4) get the same results as Bedrock against Bedrock, PocketMine-MP knockback and plugin-set values included.
- Known differences from BDS, on purpose: a player can hit another player up to 8 blocks away, PocketMine-MP's reach (BDS misses at 7 blocks), which is kinder to players with lag; the knockback of a sprint hit is 0.4 like PocketMine-MP (BDS pushes it 0.6 sideways and 0.32 up), set `player.knockback: vanilla` for the vanilla sprint push; and a shield used from the main hand blocks (Java players raise it that way; Bedrock clients raise it by sneaking).

## API
- Additions only: `Living::hasVanillaKnockback()`, `Living::setVanillaKnockback()` (internal), `Living::isDefaultKnockback()`, `Mob::lastMeleeHitHasDefaultKnockback()` (protected), `ProtectionEnchantment::getBedrockProtectionFactor()`, `Armor::getBedrockEnchantmentProtectionFactor()`, `Projectile::getHitDamage()` (protected), `YmlServerProperties::PLAYER_KNOCKBACK`.
